## 修订摘要（v0.2 → v0.3）

1. **宿主运行时切换为 DeepSeek Harness（DSH）**：整树移除 `vendor/codex-rs`（76 MB / 91 个 `codex-*` crate / 16 个 `rama-*` crate），改用 MIT 许可的 `@deepseek-ai/dsh` 作为进程级智能体循环、会话管理与 Web UI 宿主；由 `tools/loop/check-no-harness.py` 强制门禁。
2. **进程级 MCP 确定性边界（`shangyi-mcp`）**：新增第 15 个 Rust crate `shangyi-mcp`（`shangyi mcp-serve`），通过 JSON-RPC 2.0 over stdio 向 DSH 暴露 **39 个领域工具**与 **MCP Resources**（35 篇博弈论知识库 + 4 套行业剧本）。数值计算、阶段闸门、假设校验与追加式案例日志（`case.jsonl`）100% 留在纯 Rust 进程内。
3. **双通道真人 Checkpoint 与可信用户输入账本**：通过 DSH 宿主插件 `@shangyi/dsh-plugin-shangyi`（鉴权端点 `POST /api/shangyi/checkpoint` + `session/event` 真实用户消息监听）与 `shangyi-mcp` 增量日志同步，打通 Web 工作台按钮审批与对话确认双通道，确保 `actor = "user"` 不可由模型伪造。
4. **知识库 + MCP Resources + 受控项目级 Skills 双轨架构**：保留 35 篇 `shangyi/kb/*.md` 供 `kb_retrieve` BM25/图检索，同步暴露为 `shangyi://kb/<slug>` 资源，并将咨询沟通规程与开店选址规程封装为受控项目级 Skills（`dsh/skills/`）。
5. **宣纸·墨玉三栏决策工作台（`shangyi-web`）**：基于 DSH 客户端插件机制交付 `@shangyi/dsh-plugin-shangyi`、`@shangyi/dsh-plugin-shangyi-shell`、`@shangyi/dsh-plugin-shangyi-workbench` 与内嵌动态图标集 `shangyi-icons`（六枚印记：`弈`、`算`、`判`、`证`、`知`、`档`）。
6. **双模型路由支持**：同时支持本机 **Magpie Gateway**（`http://127.0.0.1:3425/v1` OpenAI 兼容网关）与官方 `DEEPSEEK_API_KEY` / GLM 路由。

## 1. 产品定位与两条非妥协铁律

**商奕（ShangYi）** 是面向中小微企业经营者与商业分析师的 **博弈论商业/金融决策咨询 Agent**。用户无需掌握博弈论术语或编写公式，系统即可围绕调价应对、竞争研判、门店选址进入、租约/采购谈判及费用核算场景，完成 **信息核验（eval）→ 均衡与反应预测（prediction）→ 稳健对策建议（recommendation）** 全链路交付。

### 1.1 铁律一：LLM 绝不算数（确定性数值主权）

- 大语言模型仅承担意图理解、公开信息采集编排、结构化建模提案（`GameSpec` / 成本科目）与自然语言解读。
- 一切进入结论或报告的数值——包括纳什均衡（纯策略/混合策略精确有理数与浮点表示）、量化反应均衡（QRE）、防悔下界、多重均衡融合概率、蒙特卡洛区间、单参数翻转阈值、租金换算、期间累计现金占用与盈亏平衡点——**必须逐字引自 `TrustLevel::Engine` 的 Rust 确定性工具输出**。
- 工具注册表按四级可信度实施硬隔离：
  - `Engine`：纯 Rust 确定性计算，带 provenance 可进入正式报告；
  - `Sidecar`：检索、正文抓取、POI 计数与图表渲染，只供证据原料，不直接产出决策结论数值；
  - `Proposal`：`ask_user`、`swarm_run`、`request_rewind` 等行为提案，须经引擎评估或用户裁决；
  - `Exploratory`：`sandbox_exec` 隔离沙箱临时探索，报告生成器硬性拒绝读取。
- Web 工作台与宿主插件遵循只读投影原则：只展示 `case.jsonl` 中的确定性产物，不在前端重算或填补 `0`/`1`。

### 1.2 铁律二：未经确认的假设不得静默进入求解器

- `GameSpec` 中的每个收益参数与先验分布必须显式携带四类来源标签之一：
  1. `user_confirmed`（经真实用户原话或检查点确认）
  2. `public_data`（附可核验公开正文 URL 与摘录）
  3. `prior_borrowed`（借用剧本/知识库区间先验并披露适用条件）
  4. `llm_inferred`（模型推断，必须在检查点向用户显著披露并获准）
- 三个阶段检查点（`cp1` 情报与参与者确认、`cp2` 博弈结构与收益假设确认、`cp3` 预测分布与稳健性边界确认）必须由真实用户确认（`user_actor = "user"`）；仅在离线自动化测试显式开启 `--auto-approve-checkpoints` / `SHANGYI_ASSUME_YES=1` 时记录 `user_actor = "auto"`，二者在审计日志中永久区分。
- 用户硬约束（`constraint_register`）与未知收益缺口（`payoff_evidence_gaps`）仅采信来自宿主可信用户输入边界的真实原话，拒绝模型自述伪造。

## 3. 咨询流程、任务范围与双通道关口机制

### 3.1 四种任务范围（`TaskScope`）

在 `intake` 阶段，模型必须首先调用 `select_task_scope` 根据用户真实诉求分流，严禁把简单查数扩张为冗长博弈建模：

1. **`research`**：纯公开信息/政策/竞品/场地核查 → `research_task_plan` / `web_search` / `web_fetch` / `poi_survey` / `research_task_update` → `complete_task` 交付。
2. **`cost`**：纯经营成本、续租搬迁对比、盈亏平衡测算 → `business_cost` / `constraint_register` / `constraint_check` → `complete_task` 交付。
3. **`research_and_cost`**：公开样本采集（如周边铺位挂牌租金）+ 确定性成本测算 → `complete_task` 交付。
4. **`consultation`**：多方策略博弈完整咨询；支持在 `select_task_scope` 中同步选定咨询模式 `mode`（`scenario` / `whatif` / `discover`）、行业剧本 `playbook` 与待推演动作 `action`。

### 3.2 三条八阶段博弈咨询路径

| 模式（`ConsultationMode`） | 核心问题 | 阶段路径与三大检查点 |
|---|---|---|
| **`scenario`**（情景推演） | 局势可能出现哪些均衡？各有多大概率？ | `intake → intel [cp1] → model_build [cp2] → solve → select [cp3] → recommend → report → archived` |
| **`whatif`**（后果推演） | 若我方走出动作 `d`，各方将如何常规/非常规反击？ | `intake → intel [cp1] → model_build [cp2] → solve → consequence [cp3] → recommend → report → archived` |
| **`discover`**（策略发现） | 参数高度不确定时，哪条策略满意达标率最高？ | `intake → intel [cp1] → model_build [cp2] → solve → discover [cp3] → recommend → report → archived` |

若在任意阶段发现关键对手收益缺失且无法取得可靠证据，允许调用 `conditional_analysis` 诚实交付已完成条件测算与信息补齐路径，绝不填 `0` 强行求解。

### 3.3 双通道真人关口确认与可信用户账本

为解决标准 MCP stdio 无原生浏览器审批回传的问题，同时严格守住铁律二，系统实现双通道协同确认：

1. **Web 工作台审批通道（GUI 首选）**：
   - 当 `checkpoint` 工具打开 `cp1` / `cp2` / `cp3` 后，`case.jsonl` 记录 `CheckpointOpened`，工作台总览与右栏检视器立即点亮 **待确认关口卡**。
   - 用户点击「核准通过」或「驳回修订」后，浏览器请求经 DSH 鉴权的 `POST /api/shangyi/checkpoint`，由宿主插件校验当前挂起状态后原子追加 `CheckpointAnswered { user_actor: "user" }` 与（通过时）`PhaseApproved` 到 `case.jsonl`。
   - `shangyi-mcp` 在每次 `tools/call` 执行前增量读取 `case.jsonl` 新增外部事件，自动同步阶段机状态并放行后续阶段推进。
2. **对话回复与 CLI 通道（Headless / 对话兼容）**：
   - `@shangyi/dsh-plugin-shangyi` 在宿主侧监听 DSH `session/event` 中的真实用户输入事件（排除 `runtime-context` 系统注入），将真实用户原话写入受控可信账本 `$SHANGYI_HOME/runtime/trusted_user_inputs.jsonl`；同时提供 `shangyi checkpoint` CLI 子命令供终端直接审批。
   - `shangyi-mcp` 自动摄取新增真实用户原话进入 `DomainExecutor`（支撑 `constraint_register` 与 `payoff_evidence_gaps`），并允许在检测到检查点打开**之后**的真实用户确认原话时通过 `checkpoint` 工具完成 `actor = "user"` 结算；若无真实后续用户确认消息，引擎硬性拒绝模型的自批请求。

3. **`@shangyi/dsh-plugin-shangyi-workbench`**：内嵌 `ShangYiIcons` 六枚动态矢量印记（零占位 SVG），渲染 **总览（八阶段进度与关口审批卡）、推演（支付矩阵与策略）、精算（均衡分布与费用明细）、假设（参数血缘表）、证据（检索来源与失败留痕）、知识库（分类索引与全文抽屉）** 六大视图。

## 6. 序列化安全、依赖许可与质量门禁

1. **Serde 含浮点枚举标注硬约束**：正式构建依赖图严禁引入 `serde_json/arbitrary_precision`（`tools/loop/check-features.py` 门禁）；任何直接或间接含 `f64`/`f32` 的 Rust `enum` 必须采用相邻标注或外部标注，并在 `dev-dependencies` 中开启 `arbitrary_precision` 执行回归拦截。
2. **许可证合规**：workspace 全面采用 MIT / Apache-2.0 兼容组件（`cargo deny check licenses sources` 门禁），严禁引入 GPL/AGPL 求解器（如 Gambit / `lrslib`）。
3. **无旧基座与挂载盘防污染**：`unsafe_code = "forbid"`；`tools/loop/check-no-harness.py` 确保零 `codex`/`rama` 依赖；外接盘开发统一经 `tools/loop/build.sh` 将 `CARGO_TARGET_DIR` 导向本地磁盘 `/tmp/shangyi-target` 并清理 `._*` AppleDouble 伴随文件。
