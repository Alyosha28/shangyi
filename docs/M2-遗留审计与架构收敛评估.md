## 1. 审计范围与核验方法

在 Issues `#1`–`#7` 落地后，为评估 M2 里程碑是否已在“核心链路 + 边缘契约 + 新手开箱”三个层面实现工程闭环，本轮对仓库执行了全链路独立走查与源码级对拍，覆盖以下五个维度：

1. **新手首次上手与独立 CLI 生命周期走查**：无预设 API 凭据状态下的 `shangyi` / `shangyi --help` / `shangyi kb` / `shangyi new` / `shangyi resume` / `shangyi report` / `shangyi start` 退出码、错误引导与目录副作用检查。
2. **`shangyi mcp-serve` 多轮 JSON-RPC 2.0 确定性走查**：在隔离 `$SHANGYI_HOME` 中通过标准输入输出协议实测完整咨询（`consultation` 三种模式 `scenario` / `whatif` / `discover`，覆盖 2 人/3+ 人博弈与混合策略均衡）、短任务（`research` / `cost` / `research_and_cost`）、双通道真人确认（`checkpoint` 经由 Web Host API 与 `shangyi checkpoint` CLI 外部写入同步）、`begin_followup_task`、`request_rewind` 与 `--resume` 断线恢复重放。
3. **DSH Profile 与受控 Skills 契约核对**：核查 `dsh/profile/`、`dsh/profile-web/` 与 `dsh/skills/` 中的系统提示词、工具名、任务范围、资源 URI 及枚举标签是否与 Rust `ToolRegistry::standard()` 和序列化 Schema 一一对应。
4. **Web 工作台宿主 API 与三端投影对齐核验**：交叉核对 `shangyi-cli`（`report_cmd.rs`）、DSH 宿主插件（`shangyi/ui/dsh-plugin-shangyi/lib/index.js`）与独立对拍脚本（`shangyi/ui/dsh-plugin-shangyi/scripts/check-projection.py`）在正常、增量合并（`merge: true`）、阶段回退（`phase_rewound`）与后续追问（`followup_task_started`）下的状态投影与 `/api/shangyi/health` Fail-Closed 行为。
5. **仓库静态护栏与真值一致性核查**：对齐工具数量、CLI 子命令数量、Crate `[lints]` 继承、术语一致性与核心模块体量分布。

## 2. M2 实际闭环状态与本轮已修复缺陷清单

### 2.1 M2 首轮交付后的真实闭环评估

基线 `36c9551`（Issues `#1`–`#7`）完成了三栏宣纸·墨玉 Web 工作台、六模块视图、`shangyi start` 单一推荐入口、`/api/shangyi/health` 基础探测以及常见 `scenario` 主路径。然而实测走查表明，M2 此前仍处于**“主干局部可用，但边缘契约、组合路径与新手开箱链路尚未闭环”**的状态：

- **新手开箱阻断**：`shangyi report <case>` 默认尝试输出 PDF 并直接报错退出；`shangyi new` 在缺凭据预检失败前提前建目录，遗留 0 字节 `case.jsonl` 孤儿目录；`shangyi resume latest` 不可用；失败提示输出模式名而非真实 `case_id`。
- **组合路径与多方数学缺陷**：`discover` 模式在先运行 `consequence_predict` 后丢失 `DiscoveryReport`；`whatif` 模式无法跳过可选 `solve` 阶段；3+ 人博弈的 `consequence_predict` 漏算焦点玩家收益且仅取角点支付；2 人全负收益场景出现归零误判；纯 `poi_survey` 短任务陷入预算/交付死锁；部分状态修改工具在 `--resume` 重放或被拒/回退后存在状态残留或不同步。
- **提示词、健康检查与投影漂移**：DSH Profile/Skills 残留若干不存在的旧工具名与范围名，且前端 `SYData.COST_TREATMENT_LABELS` 与后端枚举键名不一致；`/api/shangyi/health` 对 `mcpTools.status === 'unknown'` 误放行为健康；Rust / JS / Python 三端投影在 `merge: true`、`phase_rewound` 与 `followup_task_started` 上出现明显分叉。

以下清单汇总了本 PR 在 `fix/m2-audit-convergence` 分支已落地并附回归测试的全部修复项。

### 3.2 五大结构性复杂度与体验收敛痛点

结合上述体量分布与本轮修补经验，当前系统存在五个值得在 M3 阶段克制收敛的结构性痛点：

1. **双会话编排引擎并存（`shangyi-core/src/runner.rs` vs `shangyi-mcp/src/host.rs`）**
   - `shangyi new / resume` 使用 `shangyi-core` 中的 `SessionRunner` + `AgentLoop`（2,077 + 3,230 行）直连模型接口；而主工作台与 DSH 无头模式经 `shangyi mcp-serve` 进入 `shangyi-mcp` 中的 `SessionHost`（2,633 行）。
   - 两条会话引擎各自维护外部输入同步、检查点结算、`select_task_scope` 失败回滚、`reconsider_current_checkpoint` / `rollback_to` 产物清理与日志恢复逻辑。本轮审计中，`select_task_scope` 失败回滚与在位重审清理产物都必须在 `agent.rs`、`runner.rs` 与 `host.rs` 三处对称修补，维护成本与分叉风险随状态机规则增长呈倍增趋势。

2. **四端事件投影与 JSON 合并逻辑重复**
   - 同一套 `case.jsonl` 事件折叠与 `gamespec_build` 合并语义，目前分别存在四份独立实现：
     1. Rust 侧（`domain_exec.rs` 中的 `deep_merge` / `normalize_spec_input` 与 `report_cmd.rs` 中的 `extract_case_state` / `json_deep_merge` / `unwrap_report_spec`）；
     2. Node 宿主插件（`dsh-plugin-shangyi/lib/index.js` 中的 `projectCase` / `deepMergeJson` / `unwrapSpec`）；
     3. 独立对拍脚本（`check-projection.py` 中的 `deep_merge` / `unwrap_spec`）；
     4. Python Sidecar 控制台（`shangyi/sidecar/web_console.py` 中的 `TOOL_ARTIFACTS` 与 `_merge_spec`）。
   - 本轮审计发现的三端漂移（`merge: true` 外壳拆包、判别键 `kind`/`form` 切换替换、`phase_rewound` 与 `followup_task_started` 对 `"pending" | "answered"` 关口清理）均根源于此；且 `web_console.py` 的 `_merge_spec`（第 227–234 行）仍未实现判别键替换逻辑，长期靠人工同步四份代码不可持续。

3. **概念术语与 Wire Schema 命名分叉，以及 Workspace Lint 继承缺口**
   - **来源标签命名分叉**：`AGENTS.md`、`README.md` 与 `docs/商奕-系统设计文档-v0.3.md` 仍沿用四类概念词 `user_confirmed / public_data / prior_borrowed / llm_inferred`，而 `shangyi-gamespec/src/lib.rs`（第 48–72 行）中 `ParamSource` 的实际序列化变体为 6 种：`user_confirmed`、`confirmed_assumption`、`public_data`、`industry_prior`、`assumed`、`derived`。在修复 `dsh/profile*/cordis.patch.yml` 前，模型频繁依据文档写出不合法的 `prior_borrowed` 或 `llm_inferred`。
   - **Workspace Lint 继承缺口**：根 `Cargo.toml` 声明了 `[workspace.lints.rust] unsafe_code = "forbid"`，但 15 个 crate 中仅 `shangyi/crates/shangyi-solver/Cargo.toml` 显式声明了 `[lints]`，其余 14 个 crate 的 `Cargo.toml` 均未配置 `[lints] workspace = true`。虽然全库当前实测为 0 处 `unsafe` 代码，但编译器层面的强制继承尚未覆盖全部 14 个 crate。

4. **双 Web 入口与小白本地工具链落差**
   - 仓库内同时存在主入口 `shangyi start`（基于 DSH 宿主 + 三栏工作台，默认端口 `8791`）和独立 Python 标准库 SPA `shangyi/sidecar/web_console.py`（1,139 行，包含另一套会话/轮询/控制台 UI）。对新手而言，两个 Web 入口在路径、端口与能力边界上容易混淆；而 `shangyi start` 依赖本机预先安装全局 `dsh` 二进制与 Profile 同步。
   - 在文档导出端，虽然 `shangyi report --format md` 已开箱即用且 `pdf`/`docx` 在缺 `pandoc` 或 `xelatex` 时能 Fail-Closed 并提示中文降级方案，但默认纯净系统（无 LaTeX 发行版）下用户仍需要切入浏览器打印或自行安装数百 MB 以上的 TeX 环境才能直接获得 PDF。

5. **DSH Web 工作台实时刷新与关口续推交互中断感**
   - 审阅 `shangyi/ui/dsh-plugin-shangyi-workbench/src/50-panel.js` 可见，`WorkbenchPanel` 仅在初次挂载时拉取 `loadCases` / `loadKb` / `loadHealth`，并在 `selectedCaseId` 变化时拉取 `loadCards`（第 125–134 行），没有事件流订阅或轻量可见页轮询机制。用户在左栏连续对话推进阶段时，中栏工作台进度不会自动刷新，必须手动点击右上角「刷新」按钮。
   - 审阅 `40-view.js`（第 163–230 行）与 `50-panel.js`（第 158–200 行）可见，用户在工作台点击「核准通过」写入 `case.jsonl` 后，状态横幅提示“可在对话面板继续推进”并提供「回到对话面板」切页按钮，但不会自动向对话宿主发送续推信号；用户切回左栏后仍需手动输入一条消息（如“已核准，继续”）才能唤醒模型的下一轮 MCP 工具调用。

## 4. 克制、可落地的架构收敛路线与 M3 Issue 拆分提案

### 4.1 收敛克制原则（明确不做什么）

为避免过度重构引入新的不确定性或破坏现有测试与留档资产，后续收敛严格遵守四条克制边界：

1. **不动纯 Rust 确定性数值内核与序列化兼容**：保持 `shangyi-gamespec` / `shangyi-solver` / `shangyi-selection` / `shangyi-consequence` / `shangyi-discover` 核心算法与既有 `case.jsonl` 事件 schema 向后兼容，不更改 `ParamSource` 线上枚举名。
2. **不重写或 fork DSH 宿主**：继续通过标准 MCP stdio 协议与 DSH 宿主插件机制协作，绝不退回自建通用 Agent 循环。
3. **不引入大型前端构建链**：`dsh-plugin-shangyi-workbench` 继续保持轻量化无框架构建脚本（`src/*.js` 拼接输出），`sidecar/` 保持纯 Python 标准库定位。
4. **分步验证、增量落盘**：每个收敛点均独立成单、独立通过全部静态门禁与回归测试，**本 PR 暂不自动创建 GitHub Issue，仅提出拆分方案供审阅决策**。

### 4.2 分阶段收敛路线

- **近期（低风险对齐）**：统一基础文档与规则文件对 `ParamSource` 概念词与 Wire 6 变体的对照说明，全量补齐 14 个 Rust crate 的 `[lints] workspace = true` 编译器护栏。
- **中期（单一真相源抽取）**：以 Rust 核心实现单一 `CaseProjection` 投影模型（CLI JSON 子命令或独立轻量投影逻辑导出），逐步消解 `report_cmd.rs`、JS 宿主、`check-projection.py` 与 Sidecar 的四端重复折叠代码；并在不破坏 `shangyi new / resume` 可用性的前提下，明确 `SessionRunner` 与 `SessionHost` 的共享会话协调边界。
- **体验层（面向最终用户流畅度）**：为 Web 工作台增加低开销按需轮询/焦点刷新与关口确认后的一键续推对话引导；收敛 `sidecar/web_console.py` 的职责边界，并补齐无本地 LaTeX 环境时的浏览器打印/HTML 一键导出流。
