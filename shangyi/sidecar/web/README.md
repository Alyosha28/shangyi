# 商奕决策咨询前端（独立 Sidecar 版）

> **主入口提示**：标准 DSH 三栏工作台请使用 `shangyi start`（依赖 `dsh` 与 `dsh-plugin-shangyi*`，文档见仓库根目录 [`README.md`](../../../README.md)）；本目录为可独立运行的零构建 Python Sidecar Web 控制台（`web_console.py`，包裹 `shangyi new / solve`）。

以用户选定的 Onyx 官方 Chat UI 为主参考：左侧咨询导航、中间正文与输入、右侧证据。复现范围、来源和验证结果见 [DESIGN.md](DESIGN.md)。

## 运行

在项目根目录执行：

```sh
python3 shangyi/sidecar/web_console.py --port 8791
```

访问 http://127.0.0.1:8791 。不需要安装前端依赖或构建。正式默认端口仍是 8787。

修改 Python 后端后需要重启服务；只修改前端文件时刷新即可。新版页面要求健康接口返回 `frontend_contract: 3`，并且引擎支持 web protocol 1 或 2，旧服务不能继续发起咨询。

页面动效由随附的 `vendor/motion.min.js`（Motion 14.0.0，UMD，挂出全局 `Motion`）提供，同样**不需要安装或构建**。该文件缺失或加载失败时页面照常工作，只是不动——`js/motion.js` 会静默降级。

## 页面

- `#/run`：自由描述问题，开始新对话。
- `#/guide`：四步虚构练习，学习开场、表示不知道、修改和核对、阅读依据；不调用模型或创建真实咨询。练习结束后另填自己的问题，只交接这份新问题，不夹带练习回答。
- `#/chat/<id>`：实时追问、补充、纠正和人工确认。
- `#/run/<playbook_id>`：直接选择主题。
- `#/cases`：搜索历史咨询并按模式筛选。
- `#/case/<date>/<id>`：查看建议、报告、来源与计算依据。
- `#/activity`：进度、停止分析、日志详情。
- `#/playground`：以“比比看”的日常说法选择双方的做法及吃亏/划算程度；详细数字与算法设置收在折叠区，仍由本地确定性求解器计算。
- `#/overview`：兼容旧链接，转入新咨询体验。

## 交互与能力边界

新咨询从一段自由描述开始，由真实 agent 针对缺口追问。用户可一次回答多个信息点、纠正或表示不知道。分析期间的补充排队至下一轮接收。新通道不自动确认检查点，支持确认、修改、追问和回退裁决。消息保存在 `web-conversations`，刷新页面可返回同一对话。

用户只要求查询公开资料或整理费用时，引擎在开场选择对应任务范围，不进入完整博弈分析。结果必须来自实际检索或费用工具；未知金额、原文未取得和未列费用保留为缺口。交付后显示已完成或部分交付，输入框保持可用，等待追加期间不继续调用模型。追加要求重新建立本次任务凭据，保留已有对话和来源历史。结束对话不会把已经交付的结果改称未完成。

引导进度和真实咨询草稿分开保存。修改尚未发送时不提供确认操作；已有真实草稿冲突时必须明确选择保留或替换。存储写入失败会提示尚未保存，不冒称刷新后可恢复。可从正在进行的咨询进入引导，刷新后仍能返回原咨询并保留未发送草稿。

旧历史案例仍是只读结果，需要调整条件时另开对话。协议 2 使用持久输入文件与引擎心跳；网页服务重启后可重新连接仍存活的分析进程，不重放确认。协议 1 或分析进程已退出时仍标为中断，不冒充已恢复执行。尚不提供文件上传或语音输入。

资料与费用记录逐次保留结果和缺口，通过唯一的日期与案例标识关联原始问题，并标注该问题来自会话保存记录。复制与导出保留原问题、各次结果和依据；找到唯一关联对话时提供“回到对话”。该记录不冒称完整博弈咨询已经归档。

## 数据与引擎约定

- sidecar 使用 Python 标准库；领域求解仍只由 `shangyi solve` 执行。
- 案例从事件日志投影，不在前端生成事实、数值或置信度。
- 工具完成事件通过 call_id 与开始事件联接。
- GameSpec 可能直接位于参数或其 spec 包装内，展示同时兼容。
- 矩阵行列与均衡坐标按照 players 数组顺序，不按 JSON 对象键排序。
- 参数与检索原文保留详情；失败工具输出不列为证据。
- 理论知识库内容明确标记，不作为已观察到的经营事实。
- 背景清单与 CLI 一致：用户目录覆盖仓库剧本；末题不会在章节切换时遗漏。
- 运行注册表仍保存在服务内存中；重启不删除案例文件。

## 前端依赖策略

**保持零构建零安装**，第三方库一律随附预构建产物（现为 `vendor/` 下的 Tabler 与 Motion）。

新增库前请先确认这符合项目体量：当前前端手写 JS 约 2500 行，最大文件 500 余行，无类型系统但有 13 个 `node --test` 回归用例。此时引入构建链要付出的是**永久成本**——`python3 shangyi/sidecar/web_console.py` 一条命令就能跑起来的分发优势会变成「先装 Node、再构建、再运行」，每个后来者都要付。把这条换来的好处（类型检查、打包器、npm 生态）应当先写设计文档论证，而不是顺手加进来。

选 Motion 的实际依据：**只有它的 UMD 产物能免构建落地**。实测 `motion@14.0.0` 的 `dist/es/index.mjs` 只有一行 `export * from 'framer-motion/dom'`（裸模块名，需打包器解析），`mini` 子包更是没有独立产物、只有转发入口。因此随附 `dist/motion.js`（UMD，143 KB，gzip 后 48 KB，挂全局 `Motion`）。若将来确要引入打包器，**只改 `js/motion.js` 里 `engine()` 的取值**即可，调用点无需变动。

## 文件组织

- `index.html`、`styles.css`：应用布局及 Onyx 参考视觉层。
- `domain.css`、`js/components.js`：保留矩阵、均衡、报告与时间线组件。
- `js/ui.js`：图标、证据条目、输入与消息布局。
- `js/app.js`：路由、导航、面板和历史列表。
- `js/motion.js`：动效的唯一入口。引擎缺失、系统要求减弱动效、节点已销毁时都静默降级；**不要在视图里直接调用 Motion**。
- 动效覆盖：路由入场（`app.js`）、开场示例错峰（`run.js`）、咨询列表错峰（`cases.js`）、运行状态新条目（`activity.js`）、报告滚动揭示（`case.js`）、提示条进出场 / 状态变化 / 证据条目（`ui.js`）。
- **有意不做**：对话消息（`chat.js`）。助手消息没有稳定 id，`sig` 也不含 `messages`，无法可靠判定「哪条是新的」；而该视图有滚动锚定 `preserveScroll` 与 8 个回归用例，猜错重绘触发的代价远高于收效。此处保留轮询原有的滚动行为。
- 两条防闪铁律（改动前务必遵守）：接到会被轮询反复重设的节点上时，**只在内容真的变了才动画**（`ui.js` 的 `setStatus` / `evidence` 就是靠比较挡住的）；**绝不动 `transform` 会破坏居中的元素**（`#toast` 靠 `transform:translateX(-50%)` 居中，故只动 `opacity`）。
- `js/views/`：具体页面，`chat.js` 承担实时会话。
- `../web_chat.py`：结构化进程交互、幂等消息与会话保存。
- 详细改造与验证见项目 `research/product-design/2026-09-21-conversation-redesign.md`。
- `tests/evidence.test.mjs`、`../test_web_console.py`：证据与问题契约回归。

## 验证

```sh
python3 -m unittest discover -s shangyi/sidecar -p 'test_web*.py'
node --test shangyi/sidecar/web/tests/*.test.mjs
python3 tools/typecheck.py          # 类型体检，需要 tsc；见下
```

### 类型体检

部分 `js/**/*.js` 顶部有 `// @ts-check`，这些文件会被 `tsc --noEmit` 检查。
**这只是检查器，不是构建步骤**：不产出任何文件，`js/**/*.js` 仍是浏览器与
`node --test` 直接执行的源文件，运行与分发完全不需要 Node。

当前加入 10 个文件（`api` `components` `guide-state` `markdown` `motion`
`research` `ui` `util` `views/overview` `views/playground`），全部通过。
其中 `api.js` 是 API 边界，实测能抓到方法名打错与参数个数不对。其余 8 个仍未加入，
因为它们有一类待收口的噪声：`querySelector()` 返回 `Element`，而代码要取
`.value` / `.disabled` / `.open`。**建议不要为清掉它们而做统一取值重构**——收口后 DOM 部分仍返回 `any`，
净收益为零却要动 46 处最要紧的展示代码。理由与实测见
[前端类型化与构建可行性](../../docs/商奕-前端类型化与构建可行性-v0.1.md) §3.3（已于 2026-10-04 修订为「不建议做」）。

新增文件时请照此挑选：先加 `// @ts-check`，再跑一次 `tools/typecheck.py`；
若报错属于上述 DOM 噪声，把文件留在未加入状态即可，**不要为消灭噪声而逐点 cast**。

Tabler 基础样式遵循随附 MIT 许可（`vendor/TABLER-LICENSE`），动效引擎 Motion 遵循随附 MIT 许可（`vendor/MOTION-LICENSE`）。Onyx 作为具名界面参考，未复制其标志或企业功能。原项目内的领域组件继续使用其既有许可。

## 主动调研与经营测算

`research_record` 只接收本次 `web_fetch` 正文中逐字存在的字段与引文；登记属于原文匹配，不代表独立核实、当前有效或完整覆盖。`business_cost` 将一次性支出与月固定成本分开，并给出明确输入条件下的盈亏平衡与现金情景。未知费用不视为零，公开报价不等于成交价。实时对话右侧展示资料、来源与公式。

搜索健康检查缓存 60 秒并执行有超时的真实查询；模型状态显示未检查，模型真实工具调用自检在每次咨询启动时进行。SearXNG 后端已于 2026-10 退场，当前搜索优先使用环境变量 `BOCHA_API_KEY`，服务启动亦可从 `~/.shangyi-secrets/bocha.env` 读取密钥（不会执行文件内容，显式环境变量优先）。
