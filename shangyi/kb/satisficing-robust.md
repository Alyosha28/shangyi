# 为什么"最优解"在信息不全时是假精确

任何"最优"都是相对一个模型说的：给定需求曲线、给定对手成本、给定折现率，才解得出最优价、
最优产量。中小企业手上的这些参数大多只是估计值，误差不小。这时输出一个"最优价 = 12.7 元"
（数值仅示意）有两个坏处：那个小数点后的精度是假的；决策者会因此以为风险已经被处理掉了。

更麻烦的是，点最优常常对参数极度敏感——参数一动，最优解可能整个跳到另一个角点。于是
一个建立在错误参数上的"最优点"，不但不优，还会让你顺手否掉本来可行的方案。

# 满意化：阈值 + 候选集合（Simon 1955）

Simon 的满意化（satisficing）说的是：人不是先枚举所有选项再求最大值，而是先定一个
"可接受水平"，然后找到第一个达标的选项就停。做成决策工具，就是三步：

1. 把"什么算过得去"写成可检验的阈值——现金流覆盖倍数、回本年限、亏损概率上限。
2. 枚举约束内的候选方案，保留**全部**达标的，得到候选集合，而不是一个点。
3. 在候选集合里再按别的标准排序：最省事、最抗冲击、最快回本。

这样做的好处是责任清楚：阈值是决策者能负责的东西，模型不必假装知道精确的最优。多个候选
并存也是诚实的——信息就这么多，本来就不该收敛到唯一答案。商奕 discover 模式的
`discover_satisfice` 就是这个形状：输出**达标候选**的逐准则达标概率，不做归一化（不把候选硬压成
一个"最优概率"）。

# 稳健不等于保守（info-gap 的用法）

稳健问的是：参数错到多严重，这个选择才不达标。Ben-Haim（2006）的 info-gap 决策把这个
问题量化成一个"不确定性半径"——在这个半径内所有参数取值下仍然达标，就叫稳健；半径越大
越稳健。它和"选最坏情形下损失最小的方案"（minimax）不是一回事：minimax 只盯一个最坏点，
可能挑出一个处处平庸的方案；info-gap 问的是"离失效还有多远"。

所以稳健 ≠ 保守。一个稳健的方案可以是激进的，只要它在相当宽的不确定性范围内都还达标；
一个保守的方案也可能很脆弱，如果它只是躲开了某一个被点名的坏情形。

# 什么时候该等更多信息

多等一天，决策质量可能提高，但机会与成本也在流失。判断靠三个数比较：

- 这条信息能改变选择的程度：若答案无论如何都是同一个方案，信息价值为零；
- 拿到它的成本：钱、时间、错过的窗口；
- 等待期间的损失：租金、报价有效期、对手先动。

一个实用规则：先用敏感性扫描找出结论最敏感的那一两个参数，只对它们花钱买
信息，其余不值得等。有可靠分布时才用蒙特卡洛做概率传播——没有分布就抽样，
抽出来的是伪精度。

# 与硬约束的区别

生存线、合规红线、合同义务不是"阈值"，是**约束**。阈值可以商量（"回本期 3 年还是 3 年半
算可接受"），约束不能——亏到资不抵债不是"不达标"，是出局。所以建模顺序是：先满足硬约束
得到可行域，再在可行域内做满意化。把两者混进一张评分表加权，会让"合规风险"和"回本期差
半年"变成同一种东西，这是最容易出事的地方。

顺带一条纪律：阈值必须由决策者确认，不能由模型代定——这是**流程纪律，不是引擎保证**：
引擎不会校验你传进来的抱负水平从哪来（确认点机制见 three-checkpoints 页）。
