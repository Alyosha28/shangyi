# 闭环的三步

1. **归档时冻结预测**：把当时的均衡概率分布与判据权重快照一起存下
2. **事后回填结果**：实际实现了哪个均衡
3. **校准**：样本够了以后，把权重移向预测更准的判据

第 1 步最容易漏。若归档时只存结论不存**概率分布**，那么事后有了结果
也无从比对——那份数据对校准毫无用处。

# 冷启动期必须诚实

样本不足时权重是未校准先验。报告里必须写明这一点
（商奕用类型而非自由文本表达：`Confidence::PriorUncalibrated`），
否则读者会拿未经校准的概率当实证结论用。

「空案例库」并不等于「没有可用先验」——它表示**尚未校准**。
这两句话对决策者的含义完全不同。

# 与 [[iron-law-2-assumptions]] 的关系

校准改善的是**权重**（怎么综合判据），不改善**输入**（对手成本是多少）。
后者仍需用户确认或公开来源。把两者混淆会产生一种错觉：
"系统越用越准"，而实际上输入端的假设从未被验证过。
