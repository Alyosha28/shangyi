# 为什么这一步不能交给模型自由发挥

模型的强项是**建议结构**（有哪些玩家、可能的策略），
弱项是**给出数值**——它会编，而且编得像真的（实测：连"今天几号"都会编错）。

故本方法的划界是：

| 谁做 | 做什么 |
|---|---|
| 模型 | 提议参与者集合、策略维度、支付结构形式 |
| **确定性代码** | 计算每一个数值（见 [[support-enumeration]]） |
| **用户** | 确认每一个硬假设（见 [[three-checkpoints]]） |

# 步骤

1. **定参与者**。先用 [[value-net-parts]] 的五向扫描确认边界：
   替代者、顾客、供应商、互补者各自是谁。外部力量（监管、媒体、平台）
   只在被行动引入时展开（见 [[external-actors]]）。
2. **定策略集**。每个玩家的**可行**策略，不是"理论上可能"的策略。
   合法性依据与资源可得性都必须有（见 [[triple-filter]] 的判据）。
3. **定支付结构**。正规形（同时行动）还是扩展式（有先后）？
   现行为正规形。支付表必须**完整**——缺一格会被求解器拒绝。
4. **给每个参数标来源**。这是 [[iron-law-2-assumptions]] 的落点：
   没有来源的数值不得进入模型。

# 常见错误

- **把所有人塞进矩阵**。参与者越多，策略组合爆炸越快。
  只放**会同时反应**的玩家，其余放 `external_actors`。
- **策略集写成"能做的所有事"**。写成"会实际考虑的几档"。
- **用浮点写支付**。商奕的求解器走精确有理数，浮点会在验证时露出来。
