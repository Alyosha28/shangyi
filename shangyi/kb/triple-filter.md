# 三个判据

| 判据 | 要求 | 为什么 |
|---|---|---|
| 合法性 | 有法条/平台规则/先例依据 | "看起来合法"不是依据 |
| 资源可得性 | 行动者**确实**能执行 | 理论上可能的反击若没有执行路径，会产出虚高的反击概率 |
| 激励相容 | `P(收益 > 成本) ≥ 阈值` | 期望值比较会掩盖方差：期望正但 40% 概率巨亏的行动，对弱势方未必理性 |

最后一条用的是**概率口径**而非期望值口径。理由：中小企业主对
"最差会怎样"的敏感度远高于均值，而期望值把这个信息平均掉了。

# 被拒的提议也要留档

拒绝理由进报告——让用户看到"系统考虑过但排除了哪些路径"。
这是可信度的一部分：只展示通过项，读者无从判断筛选是否过严。

# 通过后必须重解

通过的提议会被注册回博弈（新增策略、引入 [[external-actors]]），
**旧解集随之作废**。见 [[support-enumeration]] 的完备性要求。
