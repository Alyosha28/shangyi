# 为什么要分层

同一个场景，不同客户有不同的细节点（有的允许账期、有的不允许）。
若每个客户复制一份完整剧本，那么"改一处通用逻辑"要改 N 份，
而漏改的后果是各客户之间的行为**悄悄不一致**。

分层解决它：基础层 + 客户层 + 项目层，逐层覆盖。

# 合并语义：**整行替换**，不是字段深合并

这是与 Codex 配置语义的关键差异。Codex 的层间合并是
**表递归深合并 + 非表整体替换**（已实测确认）；商奕的剧本用
**行级整行替换**。

理由：深合并在"删掉一个字段"时无能为力——你把某行写短了，
被删的字段会从下层**漏回来**，而配置文件里看不出来。

# 行必须有 id

每行带 `id` 与 `plugin`（来源层），使"这一行最终是谁写的"可查。
规则：

- 同 id ⇒ 高层覆盖低层
- 高层把某行 `active_on` 设为不包含当前平台 ⇒ 该行**被停用**（不是删除）
- 没有 id 的行 ⇒ 无法覆盖，只能并存（这是刻意的：避免"改错行"）

# 与配置审计的关系

每一行的来源进日志。审计问"这个行为是哪来的"，答案能落到**具体一层**，
而不是"配置里配的"。
